Configure

The server is configured by environment variables, all prefixed RIM_ except DATABASE_URL and the log filter RUST_LOG. In development an untracked .env file works too. This page is generated from rim_server/src/config.rs, cross-checked with the variable block of the Dockerfile; the compose stack's own settings are in deploy/.env.example.

Listening #

Where the server listens, the origin clients reach it at, and how it treats the proxy in front of it.

VariableWhat it does
RIM_SERVER_HOSTdefault 0.0.0.0

Bind address.

No doc comment in config.rs; described from the Dockerfile.

The container image sets 0.0.0.0.

RIM_SERVER_PORTdefault 8080

Listen port.

No doc comment in config.rs; described from the Dockerfile.

The container image sets 8080.

RIM_PUBLIC_BASE_URLunset by default

e.g. https://rim.example.com. Required to build clickable reset-password/invite links; without it, emails fall back to including the bare token/no link.

Dockerfile: https origin; turns server-to-server traffic on. This or RIM_KEY_LOGIN_AUDIENCES is required: the server binds 0.0.0.0 and refuses to start without an audience for key logins.

RIM_CORS_ALLOWED_ORIGINunset by default

one browser origin accepted besides the server's own (optional); the own origin is RIM_PUBLIC_BASE_URL's, else the request's Host.

No doc comment in config.rs; described from the Dockerfile.

RIM_TRUST_FORWARDED_HEADERSdefault false

When true, the server takes the real client IP for rate-limiting and IP blocks from the first entry of X-Forwarded-For; Forwarded is never read. Only enable this when a trusted reverse proxy (Nginx, Caddy, Traefik, …) is the sole entry point and replaces any X-Forwarded-For the client sent; enabling it without such a proxy lets attackers spoof their IP and defeat the rate limiters.

Dockerfile: Read the client address from X-Forwarded-For / Forwarded when true; only behind a reverse proxy that is the sole way in.

RIM_FORCE_SECURE_COOKIESdefault false

When true, all session and CSRF cookies are issued with Secure=true regardless of the incoming request scheme or X-Forwarded-Proto header. Use this for direct-HTTPS deployments where the reverse proxy does not forward the X-Forwarded-Proto header.

Dockerfile: Mark session and CSRF cookies Secure whatever the request scheme when true.

RIM_KEY_LOGIN_AUDIENCESunset by default

Comma-separated host[:port] values a key login proof may name as its audience.

The audiences a key login proof may name: this server's host[:port] as clients reach it. A proof naming another server is refused, so a server that receives a proof cannot replay it elsewhere.

RIM_KEY_LOGIN_AUDIENCES when set; otherwise the host of RIM_PUBLIC_BASE_URL; otherwise localhost:PORT and 127.0.0.1:PORT, but only for a server bound to a loopback address. Lowercased.

Refused at boot with a message naming both variables when neither is set and RIM_SERVER_HOST accepts connections from other machines.

Dockerfile: comma-separated host[:port] clients reach this server at.

PostgreSQL connection string.

Largest number of Postgres connections the server's pool opens; unset keeps the driver's default of 10.

Unset, it keeps the driver's default of 10.

Dockerfile: Size of the PostgreSQL pool.

RIM_DATA_DIRdefault ./data

Data directory.

No doc comment in config.rs; described from the Dockerfile.

The container image sets /app/data.

RIM_STORAGE_LOCAL_PATHdefault $RIM_DATA_DIR/files; this image sets /app/data/uploads

Directory of uploaded files (attachments, custom emoji, plugin bundles), created when missing; unset uses files under RIM_DATA_DIR.

Unset, it uses `files` under `RIM_DATA_DIR`.

Dockerfile: Directory of uploaded files.

The container image sets /app/data/uploads.

RIM_MAX_WORKSPACE_STORAGE_BYTESdefault 1073741824

Dockerfile: Bytes of attachments and plugin bundles one workspace may store.

RIM_SERVER_KEY_FILEdefault <RIM_DATA_DIR>/server-key.json

Path of the server key file. Default <RIM_DATA_DIR>/server-key.json.

Dockerfile: Server key file; keep the data directory on a volume, the key is the server's identity.

RIM_FRANKING_KEY_FILEdefault <RIM_DATA_DIR>/franking-key.json

Path of the franking key file. Default <RIM_DATA_DIR>/franking-key.json.

Dockerfile: Franking key file.

Signups and sessions #

Who may sign up and how, the names nobody may take, the probation of new accounts, the workspace every new account joins, how long a session lasts and how long a deleted account waits before its purge. The default is invite-only; invites come from the command line.

VariableWhat it does
RIM_OPEN_REGISTRATIONdefault false

Set RIM_OPEN_REGISTRATION=true to enable open signup.

Dockerfile: Let anyone sign up, rate-limited, when true.

RIM_REGISTRATION_POW_BITSunset by default

Leading zero bits a key-only signup's proof-of-work needs; set, it turns on pow registration. 1 to 40.

Dockerfile: turns on proof-of-work signups with that many leading zero bits.

RIM_SIGNUP_REQUIRE_KEYSdefault true

Refuse every password signup, so new accounts sign up with a key only; unset is true. Password sign-in of existing accounts is unaffected.

Whether password signups are refused: RIM_SIGNUP_REQUIRE_KEYS, true when unset.

Dockerfile: Refuse every password signup, so accounts sign up with a key; password sign-in of existing accounts still works.

RIM_DEFAULT_WORKSPACEdefault none

The id of a workspace on this server that every new account joins as a member, with its public channels, whichever way it signs up. Unset keeps signups as they are: a new account joins only the workspace its invite names. The server refuses to start when the workspace does not exist here or is the direct space.

RIM_DEFAULT_WORKSPACE, trimmed; None when unset or blank. Whether the workspace exists is checked against the database at start.

Unset, it keeps signups as they are: a new account joins only the workspace its invite names.

Refused at boot with a message naming the variable when the value is not a workspace id.

Dockerfile: id of a workspace here every new account joins as a member; one that does not exist stops the server at boot.

RIM_DEFAULT_WORKSPACE_FILEdefault none

A JSON file describing the default workspace: its name, DM policy and channels. While nobody has claimed it, each start writes a single-use owner claim link to <RIM_DATA_DIR>/owner-claim.txt; the account that signs up through the link creates the workspace and owns it, and every later start applies the file to it again. Unset, no file is read. Cannot be set together with RIM_DEFAULT_WORKSPACE.

Where the default workspace comes from: the workspace RIM_DEFAULT_WORKSPACE names, the definition RIM_DEFAULT_WORKSPACE_FILE holds (read and checked here, its claim link file in the data directory), or neither.

Refused at boot with a message naming both variables when both are set, the message of default_workspace, or one naming the file and the field it refuses.

Dockerfile: JSON definition of the default workspace; unclaimed, each start writes a single-use owner claim link to <RIM_DATA_DIR>/owner-claim.txt; an invalid file stops the server.

RIM_RESERVED_NAMESdefault none

Comma-separated usernames and display names signups and profile edits refuse, with each followed by -, _, . or a space.

RIM_RESERVED_NAMES, compared case-insensitively after NFKC normalisation; nothing is reserved when it is unset or blank.

Refused at boot with a message naming the variable when an entry is empty, as in rim,,admin.

Dockerfile: comma-separated usernames and display names signups and profile edits refuse, also followed by -, _, . or a space; an empty entry stops the server at boot.

RIM_PROBATION_HOURSdefault off

Hours after its creation during which an account cannot create a workspace, write a workspace's shared state or send a DM request to a stranger; an instance operator is never on probation. Unset or 0 turns probation off.

Unset, it turns probation off.

Dockerfile: hours after creation during which an account creates no workspace, writes no shared workspace state and sends no DM request to a stranger; never an instance operator.

RIM_SESSION_TTL_DAYSdefault 30

Session lifetime.

No doc comment in config.rs; described from the Dockerfile.

RIM_TERMS_URLdefault none

The terms of service every signup accepts, an absolute http(s) URL, for terms hosted elsewhere.

RIM_TERMS_URL, trimmed; None when unset or blank.

Refused at boot with a message naming the variable when the value is not an absolute http or https URL with a host.

Dockerfile: absolute http(s) URL of the terms of service; set, every signup must accept it; a malformed URL stops the server at boot.

RIM_TERMS_FILEdefault none

Path of a Markdown file holding the terms of service every signup accepts. The server reads it at start, refuses to start when it is missing, unreadable, empty or larger than 64 KiB, and serves it as a page at /api/terms; that page is then the terms URL. Cannot be set together with RIM_TERMS_URL.

Dockerfile: path of a Markdown file of the terms of service, served at /api/terms, which every signup then accepts; a missing, empty or oversized file, a FILL: placeholder in it, or RIM_TERMS_URL set too stops the server at boot.

RIM_MINIMUM_AGEdefault none

The age, 13 to 21, every signup confirms the person has reached; unset asks for no confirmation. The age is self-declared: nothing checks it.

RIM_MINIMUM_AGE; None when unset.

Refused at boot with a message naming the variable when the age is outside 13..=21.

Dockerfile: age, 13-21, every signup confirms the person has reached; self- declared; outside the range stops the server at boot.

RIM_ACCOUNT_DELETION_GRACE_DAYSdefault 14

Days between an account's deletion request and its purge, 0 to 30; default 14.

Refused at boot with a message naming the variable when the value is above 30.

Dockerfile: days between an account's deletion request and its purge, 0-30; outside the range stops the server at boot.

Roles and federation #

Whether the server is a relay, a host or both, the domain of its people's handles, which servers it talks to, who outside a shared workspace may start a DM, and the per-user quotas of a relay.

VariableWhat it does
RIM_ROLEdefault both

relay, host or both (default).

Refused at boot with a message naming the value when it is not relay, host or both.

Dockerfile: relay, host or both.

RIM_HANDLE_DOMAINdefault the host of RIM_PUBLIC_BASE_URL, else localhost

The domain of this server's handles: people here are @<username>:<domain>, and the signed descriptor declares it as handleDomain. A lowercase DNS name; default the host of RIM_PUBLIC_BASE_URL, else localhost. A domain other than that host must serve {"delegate": "<this server's origin>"} at /.well-known/rim-server, or other servers show no handles for people here.

The domain of this server's handles: RIM_HANDLE_DOMAIN, trimmed and lowercased; when unset or empty, the host of RIM_PUBLIC_BASE_URL, else localhost.

Refused at boot with a message naming RIM_HANDLE_DOMAIN when the domain is not a DNS name (an IPv6 host of RIM_PUBLIC_BASE_URL is not one, and needs the variable set).

Dockerfile: domain of handles, @<username>:<domain>; another domain delegates to this server.

RIM_HOST_ALLOWED_RELAYSdefault any

Comma-separated server ids allowed on host endpoints; empty allows any relay.

Refused at boot with a message naming the first entry that is not a server id.

Dockerfile: Server ids allowed on host endpoints, comma-separated.

RIM_DM_INBOUNDdefault requests

DMs from people on other servers, and from people here who share no workspace with the recipient: open (no floor), requests (default: their first message is a request the recipient accepts), partners (only people on the servers RIM_DM_PARTNERS lists, and on this one, with a request; other servers get no identity or key package of anyone here) or none (nobody outside a shared workspace; other servers get no identity or key package). Members of a shared workspace follow the workspace's rules instead.

Refused at boot with a message naming the variable whose value is not one it takes, or the first partner that is not a server id.

Dockerfile: DMs from other servers, and from people here who share no workspace with the recipient: open, requests (their first message is a request the recipient accepts), partners (only people on the RIM_DM_PARTNERS servers and this one, with a request) or none; with partners or none other servers get no identity of anyone here.

RIM_DM_OUTBOUNDdefault allowed

DMs people here start with people on other servers: allowed (default), partners (only with people on the servers RIM_DM_PARTNERS lists) or none.

Dockerfile: DMs people here start with people on other servers: allowed, partners (only with people on the RIM_DM_PARTNERS servers) or none.

RIM_DM_PARTNERSdefault none

Comma-separated server ids the partners settings of RIM_DM_INBOUND and RIM_DM_OUTBOUND name.

Dockerfile: Server ids the partners settings of RIM_DM_INBOUND and RIM_DM_OUTBOUND name, comma-separated.

RIM_S2S_DENIED_PEERSunset by default

Comma-separated server ids refused on every server-to-server endpoint.

Refused at boot with a message naming the first entry that is not a server id.

Dockerfile: Server ids refused on every server-to-server endpoint, comma-separated.

RIM_S2S_PEER_RATE_PER_MINdefault 600

Server-to-server requests accepted per peer per minute, per node. Default 600.

Dockerfile: Server-to-server requests per peer per minute.

RIM_S2S_MAX_BODY_BYTESdefault 8388608

Largest server-to-server request body. Default 8 MiB.

Dockerfile: Largest server-to-server request body.

RIM_S2S_ALLOW_PRIVATE_ADDRESSESdefault false

Allow peers on loopback, private, link-local and unique-local addresses (development and tests only).

Dockerfile: Allow peers on private addresses when true; development only.

RIM_S2S_ALLOW_HTTPdefault false

Allow server-to-server traffic over plain http (development and tests only).

Dockerfile: Allow server-to-server traffic over http when true; development only.

RIM_S2S_DEVICE_RATE_PER_MINdefault 120

Forwarded requests accepted per device per minute. Default 120.

Dockerfile: Forwarded requests per device per minute.

RIM_S2S_SUBSCRIPTIONS_PER_PEERdefault 10,000

Active delegations one relay may hold on this host. Default 10,000.

Dockerfile: Delegations one relay may hold on this host.

RIM_S2S_PEER_DEAD_AFTER_HOURSdefault 24, from 1 to 168

Hours every delivery to a relay may fail before it is dead: host events are no longer queued for it until a delivery succeeds again. Default 24, from 1 to 168.

Dockerfile: Hours of failed deliveries before a relay is dead and gets nothing queued, 1 to 168.

RIM_RELAY_QUEUE_BYTES_PER_USERdefault 256 MiB

Bytes queued per local user before the oldest items are dropped. Default 256 MiB.

Dockerfile: bytes queued per local user before the oldest items are dropped, at least 1048576.

RIM_RELAY_RETENTION_DAYSdefault 30

Days queued items and DM requests are kept. Default 30.

Dockerfile: days queued items and DM requests are kept, 1-365.

RIM_RELAY_CARD_MAX_BYTESdefault 131072

Largest profile card, in bytes. Default and most 131072.

Dockerfile: largest profile card, 1024-131072.

RIM_RELAY_KEY_PACKAGES_PER_DEVICEdefault 100

Unclaimed one-time key packages per device and cipher suite. Default 100.

Dockerfile: unclaimed key packages per device, 1-1000.

RIM_RELAY_DEVICES_PER_USERdefault 32

Devices that are not revoked, per user. Default 32.

Dockerfile: devices per user that are not revoked, 1-64.

RIM_RELAY_FORWARDS_PER_USER_PER_DAYdefault 50000

Requests a user sends through /api/remote/… per day. Default 50000.

Dockerfile: requests a user sends through /api/remote per day.

RIM_RELAY_DM_REQUESTS_PER_DAYdefault 20

DM requests one sender principal files here per day, and invites a local user sends to people on other servers per day. Default 20.

Dockerfile: DM requests one sender files here, and invites a local user sends to other servers, per day.

Command line #

Run without arguments, rim_server (/app/rim-server in the image) starts the server. The subcommands read the same configuration and exit:

rim_server --version
rim_server invite create [--email <address>] [--max-uses <1-50>] [--expires-in-days <1-30>] [--public-url <url>]
rim_server invite list
rim_server invite revoke <invite-id>
rim_server server-key show | rotate | recover --recovery-key-file <file> [--new-recovery-key]
rim_server peer reset | block | unblock <server-id>
rim_server franking-key show | rotate
rim_server principal block <principal-id> --reason <text> [--cascade]
rim_server principal unblock <principal-id>
