Configure

The server is configured by environment variables, all prefixed RIM_ except DATABASE_URL and the log filter RUST_LOG. In development an untracked .env file works too. This page is generated from rim_server/src/config.rs, cross-checked with the variable block of the Dockerfile; the compose stack's own settings are in deploy/.env.example.

Listening #

Where the server listens, the origin clients reach it at, and how it treats the proxy in front of it.

VariableWhat it does
RIM_SERVER_HOSTdefault 0.0.0.0

Bind address.

No doc comment in config.rs; described from the Dockerfile.

The container image sets 0.0.0.0.

RIM_SERVER_PORTdefault 8080

Listen port.

No doc comment in config.rs; described from the Dockerfile.

The container image sets 8080.

RIM_PUBLIC_BASE_URLunset by default

e.g. https://rim.example.com. Required to build clickable reset-password/invite links; without it, emails fall back to including the bare token/no link.

Dockerfile: https origin; turns server-to-server traffic on. This or RIM_KEY_LOGIN_AUDIENCES is required: the server binds 0.0.0.0 and refuses to start without an audience for key logins.

RIM_CORS_ALLOWED_ORIGINunset by default

one browser origin accepted besides the server's own (optional); the own origin is RIM_PUBLIC_BASE_URL's, else the request's Host.

No doc comment in config.rs; described from the Dockerfile.

RIM_TRUST_FORWARDED_HEADERSdefault false

When true, the server reads X-Forwarded-For / Forwarded headers to determine the real client IP for rate-limiting. Only enable this when a trusted reverse proxy (Nginx, Caddy, Traefik, …) is the sole entry point; enabling it without a proxy lets attackers spoof their IP and defeat the rate limiters.

Not in the Dockerfile's variable block.

RIM_FORCE_SECURE_COOKIESdefault false

When true, all session and CSRF cookies are issued with Secure=true regardless of the incoming request scheme or X-Forwarded-Proto header. Use this for direct-HTTPS deployments where the reverse proxy does not forward the X-Forwarded-Proto header.

Not in the Dockerfile's variable block.

RIM_KEY_LOGIN_AUDIENCESunset by default

Comma-separated host[:port] values a key login proof may name as its audience.

The audiences a key login proof may name: this server's host[:port] as clients reach it. A proof naming another server is refused, so a server that receives a proof cannot replay it elsewhere.

RIM_KEY_LOGIN_AUDIENCES when set; otherwise the host of RIM_PUBLIC_BASE_URL; otherwise localhost:PORT and 127.0.0.1:PORT, but only for a server bound to a loopback address. Lowercased.

Refused at boot with a message naming both variables when neither is set and RIM_SERVER_HOST accepts connections from other machines.

Dockerfile: comma-separated host[:port] clients reach this server at.

Command line #

Run without arguments, rim_server (/app/rim-server in the image) starts the server. The subcommands read the same configuration and exit:

rim_server --version
rim_server invite create [--email <address>] [--max-uses <1-50>] [--expires-in-days <1-30>] [--public-url <url>]
rim_server invite list
rim_server invite revoke <invite-id>
rim_server server-key show | rotate | recover --recovery-key-file <file> [--new-recovery-key]
rim_server peer reset | block | unblock <server-id>
rim_server franking-key show | rotate
rim_server principal block <principal-id> --reason <text>
rim_server principal unblock <principal-id>
rim_server principal list
rim_server abuse-reports list [--open]
rim_server abuse-reports add [--principal <principal-id>] [--server <server-id>] --reason <text>
rim_server abuse-reports resolve <report-id>
rim_server audit purge [--dry-run] [--older-than-days <1-3650>]
rim_server ip block <cidr> --reason <text> [--expires-in-days <1-365>]
rim_server ip unblock <cidr>
rim_server ip list

invite create prints a signup link; with --email it admits only a password signup with that address. docs/server-identity.md explains the key and peer commands, docs/relay.md and docs/operations/relay-public.md the abuse tools, docs/operations/audit-retention.md the purge. ip block refuses an address or CIDR range, IPv4 or IPv6, on every route but /healthz (docs/self-hosting.md, "Limits and blocking").
