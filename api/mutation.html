loginWithKey

loginWithKey( proof: SignedStatementInput! passwordTicket: String keepSignedIn: Boolean! keepKeyHeld: Boolean! ): LoginPayload!

Sign in with a login statement signed by one of the account's device keys. Sets the session and CSRF cookies.

An account of this server also brings passwordTicket, from passwordLoginFinish: single use, valid for 120 seconds, and only for that account. Without one, with one that is used, expired or another account's, or for an account without a password, the answer is UNAUTHENTICATED, as for a wrong proof. Accounts of other servers sign in with the key alone.

keepSignedIn ("Keep me signed in") sets persistent cookies. Unticked, the cookies last until the browser closes and the session answers only requests that carry sessionSecret (returned here) in the X-RIM-Session-Secret header; plain file downloads, reloadSession and logout excepted. A kept session of a client that holds its own keep key (keepKeyHeld, the desktop app) gets no keepKey; a web client's kept session gets the keep key the server holds for it.

rotateIdentityKey

Append a rotation to the key log. A rotation signed by the recovery key works without a session, revokes every device and session, and enrolls the device given with it.

signupWithKey

signupWithKey(input: SignupWithKeyInput!): SignupWithKeyPayload!

Create an account from a key identity and a password: passwordRegistration is the OPAQUE RegistrationUpload registered with passwordRegistrationStart. The registration mode decides the tokens (exactly one in invite-only mode, none in open mode, one token or proofOfWork in pow mode). An instance invite bound to an email address gives the account that address (EMAIL_TAKEN when another account has it); otherwise the account has no email. Signs the new account in on the device that signed up, setting the session and CSRF cookies, and returns the account's new server share in the clear.

updateMyProfile

updateMyProfile(input: UpdateMyProfileInput!): User!

Update fields on the authenticated user's profile.

Returns the full updated User so the client can refresh local cache without an extra me { ... } round-trip.

Errors

  • UNAUTHENTICATED — no session.
  • FEATURE_DISABLED — avatarUrl given while the instance has the avatars feature off.
  • FORBIDDEN — displayName from a member whose relay is another server; their display name comes from their profile card.
  • VALIDATION — displayName > 64 chars, statusText > 256 chars, bio > 2000 chars, or avatarUrl neither empty nor the URL of one of the caller's own uploaded avatars (/api/files/avatars/<caller id>/avatar-<content hash>.<ext>, as POST /api/files/avatar answers it).
  • NOT_FOUND — caller's user row missing (should not happen in practice).
  • INTERNAL — repository failure.

Examples

mutation Update($input: UpdateMyProfileInput!) {
updateMyProfile(input: $input) {
id username displayName avatarUrl statusText bio
}
}

requestAccountDeletion

requestAccountDeletion(input: RequestAccountDeletionInput!): AccountDeletionSchedule!

Schedule the signed-in account for deletion once the grace period ends (14 days unless the operator set RIM_ACCOUNT_DELETION_GRACE_DAYS, 0 to 30). Every other session of the account ends now; this one keeps working, and cancelAccountDeletion keeps the account until the grace period ends. me.deletionScheduledFor shows the pending deletion.

Then the account is purged: its sessions, devices, keys, workspace memberships, plaintext messages, files and personal settings are removed, workspaces where it was the only member are deleted, and its username becomes free. The user row stays as a tombstone (deleted-<id prefix>, "Deleted account", no email, password or key) that cannot sign in and shows in no member list or search; it stays the author of the account's encrypted messages, which are kept so the conversations' history does not shift, and of a deleted message others replied to. The tombstone keeps the account's key identity id, so the same key identity cannot sign up on this server again.

Errors

  • UNAUTHENTICATED: no session.
  • FORBIDDEN: a person from another server, who deletes their account at their relay.
  • VALIDATION: confirmUsername is not the account's username, or the account owns a workspace that has other members: hand it over (transferWorkspaceOwnership) or delete it (deleteWorkspace) first.
  • CONFLICT: a deletion is already pending.

cancelAccountDeletion

Errors

passwordLoginStart

passwordLoginStart(principalId: String!, request: String!): PasswordLoginStart!

Start a password login, before passwordLoginFinish: the OPAQUE CredentialRequest for principalId. Every start counts as a wrong try until a login finishes: tries 1 to 3 are free, the 4th to the 9th make the next one wait (RATE_LIMITED with retryAfterSeconds), and the 10th locks the password (PASSWORD_LOCKED) until a reset with the recovery phrase. A principal without a password here gets an answer of the same shape that no password finishes. No session needed.

passwordLoginFinish

passwordLoginFinish(loginId: ID!, credentialFinalization: String!): PasswordLoginFinish!

Finish a password login with the OPAQUE CredentialFinalization. On success the tries are cleared, and the answer carries a single-use ticket for loginWithKey (valid for 120 seconds), the account's server share sealed under the login's transport key, and its rewraps. The login id is used once, whatever the outcome. No session needed. Every refusal is UNAUTHENTICATED: an unknown, used or expired login, or a wrong password.

reloadSession: ReloadSessionPayload!

After a reload, hand this session's tab the reload key its stored data is sealed under, and a new one the server keeps instead. It needs the session cookie and the CSRF header, but not the session secret, which the tab lost in the reload.
