Private by choice

Private where you choose.
Honest about the limits.

Choose who runs your workspace and what your tools can reach. Here is what RIM protects, and what it doesn't.

01 / DIRECT MESSAGES

Encrypted end to end.

Direct messages and private groups are encrypted on your devices when the person who starts them has encryption set up. Across servers they always are. Servers pass them on without being able to read them.

02 / CHANNELS

Readable by their host.

Channels, private ones too, can be read by the server that hosts the workspace. That's on purpose, so search, bots and history for new members work.

03 / TOOLS

Only what you allow.

Plugins and agents get only the access you approve. A plugin that runs programs on your computer runs with your access, so install only ones you trust.

04 / REVIEW

Not reviewed yet.

An outside review of RIM's cryptography hasn't happened yet. These are early releases.

HOW IT WORKS

Your server, their server,
one conversation.

Your app talks to one server, your relay, which holds your account. A workspace lives on a server called its host, which can be the same server or another one. Servers pass signed messages between them, so you can join a workspace anywhere without a new account.

04 / PIPELINES

When something happens,
do something.

Pick a workspace event, such as a new message or someone joining, narrow it down with filters, and add a cooldown.

Today a matching event runs commands that need no confirmation, such as searches or marking conversations read. When someone joins, a pipeline can also post a welcome as a bot.

Posting on other events, calling a web address and changing workspace state are planned. Encrypted messages can't be matched by text. See the roadmap ↗

05 / WEBHOOK FORMATS

Say what an alert
should look like.

A webhook lets another service post into a channel. Pick the ready-made GitHub or Grafana format, or write rules of your own and try them on a real delivery.

“When status is failed, post: Backup failed on {host}: {reason}.”

Webhooks only receive. They're separate from pipelines, which can't call a web address yet.

Where do plugins run?

In your app. Web plugins run sandboxed, in the desktop or web app, with the permissions and network addresses you granted. Desktop plugins that run a program run it on your computer with your account's access, including local tools and credentials.

A workspace can offer plugins through its signed list. It doesn't run them for you.

How do I install a plugin?

Open Settings → Plugins. Install from a link, or on the desktop from a folder or a Git repository. Look at the source and the permissions before turning it on.

A workspace's signed list pins a version signed by its publisher. A folder, Git or plain link install is marked unsigned.

Read the plugin guide ↗
Can a plugin read my conversations?

Only with a permission you approve. Reading encrypted direct messages and groups takes a separate permission. A plugin that can read messages may be able to send them elsewhere with its other permissions, so check who wrote it and what it asks for.

A desktop plugin that runs a program also has your account's access to files and credentials, which RIM's permissions don't limit.

Two ways to bring AI.
Both off until you choose.

  1. The agent built into the app.

    Bring your own Anthropic or OpenAI key. It works through the same commands you use and can do only what you can. Its changes wait for you to confirm them, and it runs only the plugin commands you approved. Encrypted conversations stay out until you turn it on for one.

  2. An agent you already use.

    Connect Claude Code or another agent on your computer. You pick the channels it can read. Direct messages and encrypted conversations stay closed. It asks before it posts, and runs only the plugin commands you tick.

The agent asks.

What an agent reads goes from your computer to its AI provider, not through a RIM server. RIM decides what to hand over. It can't limit where it goes after that.

Is RIM for me?

Questions people ask first.

Short answers, true for the release on this page.

Do I need a server?

Not to try it. You can create an account on the public relay, which hosts the RIM community workspace, and join or start workspaces there. It's a test run with no promise about availability, so a team that depends on RIM should run its own server, or use one someone runs for them.

Join the RIM workspace ↗Run your own server ↗
Can I use it without any AI?

Yes. AI is off until you set it up. The built-in agent needs your own key, and outside agents need you to turn on Settings → Agents in the desktop app.

Is it free?

Yes. RIM is open source under the Apache 2.0 license. Running your own server costs what the server costs, and an AI provider bills you for what you use with your key.

Can my team move over from Slack?

Not yet. RIM can't import messages from another chat app today, and the roadmap doesn't list an importer.

Read the roadmap ↗
Does it have voice or video calls?

No. RIM is text chat today. Calls are on the roadmap, under later work that isn't scheduled.

Read the roadmap ↗
